# Dentel Tech Calendar

Локальное приложение для зубных техников: календарь заказов, рабочие позиции, Pricing, архив, долги, расходы, статистика и гибкий поиск.

## Главная идея

Конечный продукт — Android-приложение под актуальную версию Android с минимальными разрешениями и без обязательных облачных сервисов.

Основной цикл разработки:

1. Реализовать и проверить функцию в локальной web-версии.
2. Прогнать автоматические и smoke-тесты.
3. Зафиксировать рабочее состояние.
4. Собрать APK.
5. Проверить на телефоне.
6. Следующие изменения снова сначала делать в web-версии.

## Ключевые документы

- `AGENTS.md` — правила работы LLM/Codex с репозиторием.
- `docs/product/PRODUCT.md` — назначение продукта.
- `docs/spec/SPEC.md` — функциональная спецификация.
- `docs/spec/BUSINESS_RULES.md` — инварианты бизнес-логики.
- `docs/design/ARCHITECTURE.md` — архитектура.
- `docs/design/DATA_MODEL.md` — логическая модель данных.
- `docs/planning/ROADMAP.md` — vertical slices и стадии.
- `docs/planning/WORKFLOW.md` — SDD/pipeline.
- `docs/qa/TEST_STRATEGY.md` — стратегия тестирования.
- `PROJECT_STATE.md` — текущее состояние проекта.
- `work/ACTIVE_TASK.md` — текущая задача.
- `work/HANDOFF.md` — передача состояния между длинными сессиями/контекстами.

## Source of truth

Текущее поведение приложения — базовый источник истины для уже реализованных функций. Если старый промпт, спецификация или тест расходится с приложением, сначала сверяются код и интерфейс, затем устаревший документ или тест приводится в соответствие. Будущие намеренные изменения сначала фиксируются в `docs/spec/` и `docs/spec/BUSINESS_RULES.md`.

## Локальная разработка

Требуется Node.js 24 LTS и npm.

```powershell
npm ci --ignore-scripts
npm run dev
```

`--ignore-scripts` нужен для воспроизводимой установки на текущей Windows-среде: npm иначе запускает автоматическую node-gyp пересборку `better-sqlite3`, хотя пакет уже содержит рабочий бинарник для Windows x64 и Node 24.

Vite открывает web-приложение на `http://127.0.0.1:5173`, Fastify API работает на `http://127.0.0.1:3000`. Оба процесса слушают только локальный интерфейс. Веб-приложение и команды подготовки тестовых данных используют одну SQLite-базу `.local/dental-tech-calendar.sqlite`; путь можно заменить переменной `DTC_DB_PATH`. `npm run db:test:reset` удаляет и пересоздаёт эту рабочую базу, а `npm run db:test:seed` заполняет её синтетическими данными. Эти команды не запускаются автоматически тестами; используй их только когда действительно нужно заменить данные текущей web-базы.

В APK приложение создаст отдельную пустую SQLite-базу в локальном хранилище телефона. Она не связана с веб-базой проекта.

Web-приложение включает календарь, заказы и работы, прайс и справочники, расходы, закрытие, долги, архив, статистику и импорт/экспорт. Веб-просмотр показывает интерфейс в рамке с пропорциями POCO X7 Pro; режим браузерной проверки `?computerUse=1` и Android APK открывают сам интерфейс без нарисованной рамки устройства.

## База и проверки

```powershell
npm test
npm run test:smoke
npm run build
```

Playwright smoke запускает отдельные локальные API и Vite-процессы на портах `3001` и `5174` с временной базой в памяти; эти процессы не создают дополнительный постоянный файл и не меняют общую веб-базу. Команды `npm run db:test:reset`, `npm run db:test:seed` и `npm run db:migrate` работают с настроенной рабочей базой; запускай их только когда необходимо изменить именно эту базу.

Android debug APK собирается через Gradle под именем `DentForLelikovsky.apk` и сохраняется в `android/app/build/outputs/apk/debug/DentForLelikovsky.apk`. Проверка разрешений и доставки напоминаний на физическом телефоне остаётся открытой; успешная сборка не заменяет проверку на устройстве.
